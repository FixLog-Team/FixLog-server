## 읽는 법

| 표기 | 의미 |
|---|---|
| **ID** | `FR-{도메인}-{번호}` 기능 요구사항 / `NFR-{번호}` 비기능 요구사항 |
| **P** | 우선순위 — `P0` 없으면 서비스 불성립 / `P1` 1차 필수 / `P2` 1차 포함하되 축소 가능 |
| **M** | 소속 마일스톤 (상위 문서 8장) |
| **AC** | 수용 기준 (Acceptance Criteria). Given-When-Then |

도메인 코드: `MIG` 기반/마이그레이션 · `WS` 워크스페이스 · `PRM` 권한 · `SHR` 공유 ·
`REV` 버전 · `AUD` 감사 로그 · `TRS` 휴지통 · `LBL` 라벨 · `AI` AI 사용량/비용 ·
`ADM` 관리자 콘솔 · `SEC` 보안 정책

> **콘텐츠 계층은 현행 유지다** (D7). 폴더가 트리를 이루고 문서는 폴더 안에 놓인다.
> 문서는 자식을 갖지 않으므로 계층 관련 신규 요구사항은 없다.

## 1. 기반 (MIG)

| ID | 요구사항 | P | M |
|---|---|---|---|
| FR-MIG-001 | Flyway를 도입하고 이후 모든 스키마 변경은 마이그레이션 스크립트로만 수행한다 | P0 | M0 |
| FR-MIG-002 | `Code` enum에 `FORBIDDEN`을 추가하고 HTTP 403에 매핑한다 | P0 | M0 |
| FR-MIG-003 | 문서·폴더 서비스의 현재 동작을 고정하는 회귀 테스트를 재작성 **이전에** 확보한다 | P0 | M0 |
| FR-MIG-004 | `FolderEntity`·`DocumentEntity`에 `workspace_id`를 부여한다 | P0 | M1 |
| FR-MIG-005 | `FolderEntity`에 materialized path(`path`)를 추가하고 이동 시 서브트리를 일괄 갱신한다 | P0 | M2 |
| FR-MIG-006 | 리포지토리에서 `create_user` 결합 조회를 전부 제거한다 | P0 | M3 |
| FR-MIG-007 | 벡터 청크 메타데이터에 `workspace_id`를 적재한다 | P1 | M4 |

**AC (FR-MIG-003)**
- Given 문서·폴더의 생성/조회/수정/이동/순서변경/삭제 경로
- When 회귀 테스트를 실행하면
- Then 각 경로의 현재 동작이 검증되며, **이 테스트가 통과하기 전에는 M1에 착수하지 않는다**

**AC (FR-MIG-005)**
- Given `/r/a/b/` 경로에 있는 폴더 b와 그 하위 서브트리
- When b를 `/r/c/` 아래로 이동하면
- Then b와 **모든 하위 폴더의 `path`가 함께 갱신**되며, 이후 권한 상속 판정이 새 경로를 따른다

**AC (FR-MIG-006)**
- Given 권한 판정으로 전환된 리포지토리
- When 리포지토리 인터페이스 전체를 검사하면
- Then `createUser`를 조건으로 갖는 조회 메서드가 **하나도 존재하지 않는다**

> ⚠️ **M2에서 리포지토리를 손볼 때 `create_user` 조건을 새로 넣지 않는다.**
> 넣었다가 M3에서 걷어내면 같은 코드를 두 번 쓰게 된다.

| FR-WS-011 | `ADMIN`은 그룹에 구성원을 추가·제거할 수 있다. 그룹은 워크스페이스 경계를 넘지 않는다 | P1 | M1 |
| FR-WS-012 | 한 사용자는 여러 워크스페이스에 속하며, 역할은 워크스페이스별로 독립이다 | P0 | M1 |

**AC (FR-WS-002)**
- Given 가입 이력이 없는 사용자
- When Google OAuth 최초 로그인이 완료되면
- Then 해당 사용자를 유일한 `ADMIN`으로 하는 개인 워크스페이스가 생성되고, 이후 폴더·문서 생성 시 기본 워크스페이스로 사용된다

**AC (FR-WS-008)**
- Given `ADMIN`이 1명뿐인 워크스페이스
- When 그 `ADMIN`이 탈퇴 또는 자기 강등을 시도하면
- Then 요청은 거부되고 워크스페이스에는 항상 최소 1명의 `ADMIN`이 남는다

**AC (FR-WS-012)**
- Given 사용자 A가 워크스페이스 X에서 `ADMIN`, Y에서 `MEMBER`인 상태
- When A가 Y에서 관리자 전용 기능을 호출하면
- Then X의 `ADMIN` 지위와 무관하게 거부된다

## 3. 권한 (PRM)

| ID | 요구사항 | P | M |
|---|---|---|---|
| FR-PRM-001 | 권한 레벨은 `OWNER` / `EDITOR` / `VIEWER` 세 가지다 | P0 | M2 |
| FR-PRM-002 | 다운로드 허용 여부는 레벨과 **독립된 별도 플래그**(`can_download`)로 관리한다 | P0 | M2 |
| FR-PRM-003 | 모든 접근 판정은 단일 컴포넌트 `PermissionEvaluator`를 통과한다. 리포지토리 쿼리에 권한 조건을 넣지 않는다 | P0 | M2 |
| FR-PRM-004 | 판정 순서는 멤버십 → 보안 정책 → `ADMIN` → 직접 권한 → 상속 권한 → 거부 순이다 | P0 | M2 |
| FR-PRM-005 | 권한 주체는 User 또는 Group이며, User 권한이 Group 권한보다 우선한다 | P0 | M2 |
| FR-PRM-006 | 폴더 권한은 하위 폴더·문서로 상속되며 문서 레벨에서 오버라이드할 수 있다 | P0 | M2 |
| FR-PRM-007 | 조상 폴더 권한 조회는 폴더 깊이와 무관하게 단일 쿼리로 수행한다 | P0 | M2 |
| FR-PRM-008 | 워크스페이스 비멤버의 리소스 접근은 `FORBIDDEN`이 아니라 `NOT_FOUND`로 응답한다 | P0 | M2 |
| FR-PRM-009 | 모든 목록 조회는 현재 컨텍스트 워크스페이스로 범위가 한정된다 | P0 | M3 |
| FR-PRM-010 | 워크스페이스 `ADMIN`은 해당 워크스페이스 내 전 리소스에 접근할 수 있고, 이 접근은 관리자 접근으로 감사 로그에 기록된다 | P1 | M2 |
| FR-PRM-011 | 폴더·문서 생성자(`create_user`)는 작성자 정보로만 유지되며 접근 제어에 사용되지 않는다 | P0 | M3 |

**AC (FR-PRM-002)**
- Given 문서 D에 `VIEWER` + `can_download = false` 권한을 가진 사용자
- When 해당 사용자가 D를 조회하고 이어서 다운로드를 시도하면
- Then 조회는 성공하고 다운로드만 `FORBIDDEN`으로 거부된다

**AC (FR-PRM-006)**
- Given 폴더 F에 `EDITOR` 권한이 부여된 사용자, F 하위에 문서 D가 있는 상태
- When 사용자가 D를 편집하면
- Then D에 직접 부여된 권한이 없어도 상속으로 허용된다
- And D에 `VIEWER` 오버라이드가 설정되어 있으면 상속보다 오버라이드가 우선하여 편집이 거부된다

**AC (FR-PRM-008)**
- Given 워크스페이스 X에 속하지 않은 사용자와 X의 문서 D
- When 사용자가 D를 조회하면
- Then `NOT_FOUND`가 반환되며, 응답으로 D의 존재 여부를 판별할 수 없다

**AC (FR-PRM-009)**
- Given 워크스페이스 X와 Y 모두에 문서를 가진 사용자
- When 컨텍스트가 X인 상태로 문서 목록을 조회하면
- Then Y의 문서는 권한이 있더라도 목록에 포함되지 않는다

## 4. 공유 (SHR)

| ID | 요구사항 | P | M |
|---|---|---|---|
| FR-SHR-001 | `OWNER`는 문서에 대해 다른 사용자·그룹에게 권한을 부여할 수 있다 | P0 | M4 |
| FR-SHR-002 | `OWNER`는 폴더를 공유할 수 있으며, 하위 폴더·문서는 상속으로 접근 가능해진다 | P0 | M4 |
| FR-SHR-003 | 권한 부여 시 레벨과 다운로드 허용 여부를 함께 지정한다 | P0 | M4 |
| FR-SHR-004 | 부여된 권한을 회수할 수 있다 | P0 | M4 |
| FR-SHR-005 | "나와 공유됨" 목록 — 자신이 생성하지 않았으나 권한을 가진 폴더·문서를 조회할 수 있다 | P1 | M4 |
| FR-SHR-006 | 의미 기반 검색은 권한 **사전 필터**를 적용한다. 사후 필터링을 사용하지 않는다 | P1 | M4 |
| FR-SHR-007 | 공유 대상은 같은 워크스페이스의 구성원·그룹으로 한정된다 | P0 | M4 |

**AC (FR-SHR-002)**
- Given 폴더 F 아래에 문서 D1, D2가 있는 상태
- When F를 `VIEWER`로 공유하면
- Then 대상자는 D1·D2를 조회할 수 있고, 이후 F에 추가되는 문서에도 자동으로 같은 권한이 적용된다

**AC (FR-SHR-006)**
- Given 워크스페이스에 100건의 문서가 있고 사용자가 그중 3건에만 권한을 가진 상태
- When 상위 10건을 요구하는 의미 기반 검색을 실행하면
- Then 후보 집합이 권한 있는 3건으로 **먼저** 좁혀진 뒤 유사도 상위가 계산되며, 결과가 비지 않는다

**AC (FR-SHR-004)**
- Given 문서 D에 `EDITOR` 권한을 받은 사용자
- When `OWNER`가 그 권한을 회수하면
- Then 사용자의 이후 D 접근은 즉시 거부되고, 회수 사실이 감사 로그에 남는다

**AC (FR-TRS-005)**
- Given 폴더 F와 그 안의 문서 D가 함께 휴지통에 있는 상태
- When D만 복원하면
- Then D는 루트로 복원되고, 삭제된 F 안으로 되살아나지 않는다

**AC (FR-TRS-006)**
- Given 리비전과 벡터 청크가 존재하는 문서
- When 영구 삭제하면
- Then 문서·리비전·벡터 청크가 모두 제거되고 검색 결과에도 잔존하지 않는다

## 12. 비기능 요구사항 (NFR)

| ID | 요구사항 | 검증 방법 |
|---|---|---|
| NFR-001 | 권한 상속 조회는 폴더 깊이와 무관하게 **단일 쿼리**로 조상 집합을 얻는다 | materialized path 기반 구현 + 깊이 5 이상 트리 테스트 |

| NFR-004 | API Key 원문은 응답·로그·예외 메시지 어디에도 노출되지 않는다 | 마스킹 테스트 + 로그 검사 |
| NFR-005 | 권한 판정 실패의 응답 코드는 일관된다 — 비멤버 `NOT_FOUND`, 멤버의 권한 부족 `FORBIDDEN` | 판정 경로별 응답 코드 테스트 |
| NFR-006 | 권한 판정·워크스페이스 격리 테스트를 각 마일스톤 종료 시점에 확보한다 | M1·M2·M3 각각의 격리 테스트 |
| NFR-007 | 스키마 변경은 Flyway 마이그레이션으로만 이루어지며 `ddl-auto`는 검증 모드로 전환한다 | 설정 확인 |

## 13. API 개요

> 상세 스펙(요청/응답 스키마)은 구현 시 `docs/api/FRONTEND_API_GUIDE.md`에 반영한다.
> **기존 `/folders/*`, `/api/documents/*` 경로는 유지된다** (D7).

### 13.1 신규

| 그룹 | 엔드포인트 | 관련 FR |
|---|---|---|
| 워크스페이스 | `GET/POST /workspaces`, `GET /workspaces/{id}` | FR-WS-001,004 |
| 멤버십 | `GET/POST /workspaces/{id}/members`, `PATCH/DELETE /workspaces/{id}/members/{userId}` | FR-WS-005~009 |
| 그룹 | `GET/POST /workspaces/{id}/groups`, `PATCH/DELETE .../groups/{groupId}`, `POST/DELETE .../members` | FR-WS-010,011 |
| 권한·공유 | `GET/POST /documents/{id}/permissions`, `DELETE /documents/{id}/permissions/{permissionId}`, 폴더 동일 | FR-SHR-001~004 |
| 공유 목록 | `GET /documents/shared-with-me` | FR-SHR-005 |
| 리비전 | `GET /documents/{id}/revisions`, `GET .../revisions/{revId}`, `POST .../revisions/{revId}/restore` | FR-REV-004~006 |
| **휴지통** | `GET /trash`, `POST /trash/{resourceType}/{id}/restore`, `DELETE /trash/{resourceType}/{id}` | FR-TRS-003,004,006 |
| **라벨** | `GET/POST /workspaces/{id}/labels`, `POST/DELETE /documents/{id}/labels`, `GET /documents?label=` | FR-LBL-001~005 |
| 감사 로그 | `GET /workspaces/{id}/audit-logs` | FR-AUD-005 |
| AI 키 | `GET/POST /users/me/ai-keys`, `DELETE /users/me/ai-keys/{keyId}` | FR-AI-002~004 |
| AI 사용량 | `GET /workspaces/{id}/ai-usage` | FR-AI-008 |
| 보안 정책 | `GET/PATCH /workspaces/{id}/security-policy` | FR-SEC-001,005 |
| 관리자 현황 | `GET /workspaces/{id}/admin/permissions`, `.../shares`, `.../stats` | FR-ADM-002,003,005 |

### 13.2 변경

| 대상 | 변경 내용 |
|---|---|
| `/folders/*`, `/api/documents/*` 전체 | 소유자 결합 조회 → 권한 판정 + 워크스페이스 범위 한정 |
| `/api/documents/{id}/download` | 다운로드 권한(`can_download`) + 정책 확인 + 워터마크 + 감사 로그 |
| 폴더·문서 삭제 | 휴지통으로 이동 (FR-TRS-001,002) |
| `/search` | 권한 사전 필터, 라벨·기간 필터 추가 |
| `/ai/*` | 권한 판정, 모델 계층 선택, 자격증명 런타임 구성, 사용량 기록, 한도 확인 |
| `/users/me` | 소속 워크스페이스·역할 포함 |
